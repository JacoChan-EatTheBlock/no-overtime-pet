# 12｜通知、权限与隐私

## 1. 目标

以最少打扰的方式提醒待办和跑路时间，同时让用户清楚控制桌面识别、截图上传、好友状态和数据留存。

## 2. 权限分层

不得使用一个笼统“同意所有权限”开关。至少分为：

| 权限 | 默认 | 说明 |
|---|---|---|
| macOS 前台应用类别 | 启用活动识别时开启 | 只保存派生类别，不保存完整应用清单 |
| Input Monitoring | 关闭；启用输入动作时请求 | 只做键鼠活跃度聚合，不采具体键值/坐标 |
| Accessibility | 关闭；启用增强识别时请求 | 只在本机内存处理允许的窗口上下文 |
| 浏览器类别 | 关闭 | 不保留完整 URL |
| Screen Recording 与在线截图视觉识别 | 关闭 | 单独授权；先打码、无留存，拒绝时不得截图 |
| 允许好友查看我的活动状态 | 好友功能开启时询问 | 只广播模糊状态，可独立关闭 |
| 在桌面显示好友桌宠 | 开启 | 只控制本机显示，不改变自己的广播 |
| macOS 系统通知 | 首次需要发送提醒时请求 | 可按类型关闭；拒绝不影响应用内提醒 |

撤销权限后立即停止对应采集。账号与计划数据以服务端记录为权威来源；MVP 账号页不提供独立的数据导出、活动历史删除或设备管理面板。

## 3. 首次引导

建议分时询问：

1. 首次运行只完成账号和基础功能说明；菜单栏入口不需要伪装成系统权限，也不一次性索要全部权限；
2. 用户启用拍键盘或离开判断时，解释并请求 Input Monitoring；
3. 用户启用增强窗口识别时，解释并请求 Accessibility；
4. 用户选择“高准确识别”时才请求 Screen Recording，并再次确认截图会在打码后发送给在线模型；
5. 首次需要发送系统提醒时才请求通知权限；
6. 用户添加首个好友时确认广播范围；
7. 每个权限页展示“采什么、不采什么、发给谁、保存多久”。

系统权限与产品开关必须分开显示：产品开关表达用户意愿，系统权限表达 macOS 当前实际授权。应用不能把本地 `enabled=true` 当作已经获得系统权限，也不能通过循环弹窗强迫用户授权。权限被拒绝或撤销时，设置页应提供前往系统设置的入口，并在应用重新获得焦点或重启后刷新状态。

## 4. 通知类型

| 通知 | 默认 | 示例 |
|---|---|---|
| 下一个任务开始 | 开启 | “该换下一摊活了” |
| DDL 风险 | 开启 | “照这个速度，可能赶不上 DDL” |
| 午休开始/结束 | 开启 | “窝囊费暂停，先去吃饭” |
| 下班提醒 | 开启 | “可以跑路了” |
| 加班扣减 | 开启，低频 | “窝囊费正在倒扣” |
| 好友成功跑路 | 关闭 | 避免社交通知泛滥 |
| 商店上新 | 关闭 | MVP 可不实现 |

加班提醒最多按策略低频出现，不得每分钟弹窗施压。

## 5. 数据最小化与留存

| 数据 | 建议留存 |
|---|---|
| 原始截图 | 0；请求完成立即释放 |
| 具体窗口标题/URL | 默认 0；不落盘 |
| 本地活动特征 | 7 天滚动，可关闭 |
| 活动分类 | 90 天或随账号删除策略处理 |
| 任务和日程 | 用户主动删除前 |
| 经济账本 | 依法务/审计策略长期保留，前台可导出 |
| 好友 presence | Redis 短 TTL，不作为历史轨迹 |
| 安全审计日志 | 建议 30–90 天，去内容化 |

具体留存期限上线前需法律与隐私评审。

## 6. 好友可见性

用户使用两个语义独立的复选设置：

- `shareActivityWithFriends`：“允许好友查看我的活动状态”。关闭后停止向所有好友广播自己的活动与动作；
- `showFriendPetsOnDesktop`：“在桌面显示好友桌宠”。关闭后只影响本机显示，不改变自己的广播状态。

对单个好友选择“不对其展示”时，只关闭当前用户到该好友的活动投影，好友关系保留，反向投影不受影响。

无论何种模式，任务标题、工资、余额、DDL、应用和窗口内容都不可见。

## 7. 在线模型供应商要求

- 提供关闭数据训练/留存的企业或 API 模式；
- 传输加密；
- 记录供应商、区域、modelVersion 和调用目的，不记录图片本身；
- 供应商变化需更新隐私说明并重新评估；
- 不把视觉模型输出的 OCR 文本写入日志；
- 请求失败时不得自动切换到隐私条款更宽松的供应商。

## 8. 账号与服务端数据

- 查看和修改用户名、好友码关联资料及个人设置；
- 账号、任务、日程、好友关系和经济记录以服务端为权威来源，本地只保留必要缓存；
- MVP 不提供独立的数据导出、活动历史删除、设备会话列表或“退出其他设备”入口；
- 用户仍可注销账号；注销后立即停止联机展示，后台按政策异步删除或去标识化；
- 经济账本如因审计需要保留，应与可识别账号解绑并在政策中说明；
- 若发行地区法律要求数据访问或导出，必须在上线前补充合规通道，但不擅自扩展当前账号页面。

## 9. 安全要求

- refresh token 等本机凭据通过 Electron `safeStorage` 使用 macOS Keychain，禁止明文写入 SQLite、localStorage 或日志；
- 本地 SQLite 中敏感字段加密或使用受限密钥；
- 服务端传输 TLS；
- 服务端按用户和好友关系授权，不相信客户端字段过滤；
- 日薪、任务和账本不得进入普通埋点；
- 错误上报前做字段级脱敏。

## 10. 验收条件

1. 截图识别未授权时无截图网络请求。
2. 撤销输入权限后 1 秒内停止采集。
3. 好友状态抓包只含共享契约允许字段。
4. 原始截图、窗口标题和 URL 不出现在日志、Sentry 或数据库。
5. 关闭活动广播或对单个好友“不对其展示”后，目标好友在 3 秒内看不到当前用户的活动投影。
6. 关闭桌面好友桌宠显示后，本机不再渲染好友角色，但自己的广播设置保持不变。
7. 两个好友可见性选项使用独立复选控件，不得合并。
8. 产品内不存在活动纠正或类别改写入口。
9. 每项权限都有独立开关和清晰说明。
10. 未获得 Input Monitoring、Accessibility 或 Screen Recording 时，不启动对应采集，任务、排程、经济和基础桌宠仍可使用。
11. 系统设置中撤销权限后，应用重新聚焦或重启能够显示真实授权状态，不把旧的本地开关显示成已授权。
12. 签名、公证后的 DMG 安装版本能够稳定访问 Keychain；升级后不会因为签名身份变化反复请求凭据访问。

## 12. 依赖

- 活动识别；
- 好友实时状态；
- 工作日通知；
- 账号和数据删除 API。
