# PRD 合集说明

## 1. 目的

本目录把《不要加班》拆成可独立实现、可独立验收、可通过共享契约合并的功能 PRD。每个模块只定义自身职责；跨模块公共定义统一放在 `01-shared-contracts.md`。

## 2. 强制阅读顺序

1. 根目录 `不要加班_组合式PRD_v2.0.md`；
2. `00-product-overview.md`；
3. `01-shared-contracts.md`；
4. 当前开发模块；
5. 当前模块引用的 API、数据字典、测试和数据集文档。

## 3. 文档标签

| 标签 | 含义 | 开发处理 |
|---|---|---|
| `[已确认]` | 用户已明确决定 | 不得自行更改 |
| `[建议]` | 当前推荐实现 | 可在评审中替换，但必须说明影响 |
| `[待确认: ID]` | 缺少产品决定 | 查看是否标记阻塞 |
| `[MVP]` | 首个可交付版本必需 | 纳入 MVP 范围 |
| `[后续]` | 不进入 MVP | 不得顺手实现 |
| `[隐私]` | 涉及用户敏感数据 | 必须满足权限和留存规则 |
| `[经济]` | 影响余额、价格或结算 | 必须具备账本、幂等和审计 |

## 4. 模块依赖规则

```text
共享契约
  ├─ 账号好友 ─────────────┐
  ├─ 工作设置 ── 经济商店 ├─ API / 数据字典 / 测试
  ├─ 待办 ── AI 分析 ── 排程 ┤
  └─ 活动识别 ── 桌宠动作 ── 联机排排坐
                  └─ 美术资产契约
```

1. 所有模块可依赖共享契约。
2. 功能模块不得反向修改共享契约；变更须单独提交契约提案。
3. AI 分析只产生建议，不直接写入正式任务或正式日程。
4. 活动识别产生内部分类；桌宠动作和好友状态只消费脱敏结果。
5. 经济余额只由服务端账本变更，客户端不得直接设置余额。
6. 实时事件是表现层加速，不是任务、购买或结算的唯一事实来源。

## 5. 单模块 PRD 的固定结构

每份功能 PRD 应包含：

1. 目标和非目标；
2. 用户故事；
3. 业务规则；
4. 状态或流程；
5. 输入、输出和失败模式；
6. 数据模型与事件；
7. 隐私、安全和降级；
8. 验收条件；
9. 待确认项；
10. 对其他模块的依赖。

## 6. 版本与兼容

- 文档版本：`major.minor`，破坏性产品规则变更提升 major。
- 数据契约：每个对象带 `schemaVersion`。
- 策略：排程、分类、定价和结算带独立 `policyVersion`。
- 静态目录：带 `catalogVersion`。
- 动画资源：带 `assetVersion`。
- 消费方必须容忍新增可选字段；删除、改名、改变字段语义属于破坏性变更。

## 7. 合并工作流

1. 模块分支只改模块文件、必要共享类型和对应测试。
2. 若需要共享契约变更，先提交契约变更并明确受影响模块。
3. 服务端接口以 OpenAPI/JSON Schema 为可执行契约；WebSocket 事件以事件 Schema 为准。
4. 数据库迁移必须向前兼容一个客户端版本。
5. 合并前运行模块测试、契约测试和跨模块关键路径测试。
6. 经济与隐私变更必须单独列出风险，不与无关重构混合。

## 8. 单一事实来源

| 事实 | 唯一可信来源 |
|---|---|
| 用户设置、日薪、工时 | 服务端用户设置版本；离线时使用最近同步副本 |
| 任务及完成状态 | 服务端任务记录 |
| AI 建议 | AI Proposal，尚非正式事实 |
| 正式日程 | 用户确认或允许自动激活后的 Schedule Revision |
| 活动分类 | 本地识别器最近一次有效结论 |
| 好友可见状态 | 本地脱敏投影，经实时服务转发 |
| 窝囊费余额 | 服务端规范化等价时间账本 |
| 加班奖励池金额 | 服务端人民币分贡献与结算账本 |
| 购买结果 | 服务端 Purchase + Ledger 原子事务 |
| 装备外观 | 服务端装备记录；客户端按资源版本渲染 |
| 工作日边界 | 固定 `Asia/Shanghai`；只有 App 已连接会话区间计提 |
| 角色动作 | 128×128 透明 GIF + Manifest；状态机按 `PetAction` 切换 |

## 9. 数据集目录

`datasets/` 中的文件用于给开发、测试和 AI 提供结构示例。它们不是生产数据，也不能未经校验直接导入生产环境。字段约束以共享契约和数据字典为准。
