# 《不要加班》UI 全套还原规范 v1.0

> 状态：实现基线  
> 最后更新：2026-08-29  
> 适用范围：`design/image2-ui-v1/`、`design/image2-ui-v2-comments/` 中的现有参考图  
> 产品平台：Windows x64 可分享 Demo，但不把产品自有像素 UI 改成 Windows 原生视觉

## 1. 目的

本规范用于把现有 28 张 UI 参考图还原为可运行、可点击、可由后续开发者接入真实功能的 Electron + React 界面。

当前阶段只实现：

- 产品自有视觉与布局；
- 页面之间的主要演示流程；
- 表单、标签页、菜单、弹窗、选择和拖动等可见交互；
- 稳定的 Mock 数据和事件接口；
- 同视口视觉对照所需的固定页面状态。

当前阶段不实现：

- 真实注册登录、Token、Windows DPAPI `safeStorage`；
- AI 调用、确定性排程器和活动识别；
- 服务端任务、好友、钱包、购买和奖励池；
- Windows 系统托盘、透明窗口层级、活动能力状态和 Demo 交付能力；
- PRD 中尚未确认的业务规则。

UI 不得为了演示而复制一套临时业务逻辑。后续功能接入应替换 Mock 数据源与事件处理器，而不重写页面结构和视觉组件。

## 2. 权威顺序

发生冲突时按以下顺序处理：

1. Magnus 最新明确决定；
2. 根目录 `不要加班_组合式PRD_v2.0.md` 与 `docs/prd/01-shared-contracts.md`；
3. 对应功能模块 PRD；
4. `design/image2-ui-v2-comments/` 中的修订图；
5. `design/image2-ui-v1/` 中的原始参考图；
6. 本规范中的还原建议。

视觉稿负责布局、构图、色彩和层级；新版 PRD 负责流程、权限、文案和功能边界。不得为了像素相似而重新加入已被 PRD 废止的入口。

## 3. 已确认的视觉与平台边界

### 3.1 保留的产品视觉

- 暖米白纸张式面板；
- 深棕色像素描边与阶梯切角；
- 青绿色主操作；
- 珊瑚红色危险操作；
- 低饱和绿色成功状态和橙色风险状态；
- 黑色高对比中文正文；
- 像素角色、像素道具、像素状态图标；
- 桌宠气泡、排排坐、商店卡片、帽子堆叠等既有构图；
- 克制、自嘲但不羞辱用户的文案语气。

### 3.2 不做的视觉迁移

- 不改成 Windows 原生设置页风格；
- 不使用毛玻璃、交通灯按钮、系统侧栏或 SF Symbols 替换既有产品视觉；
- 不因首发平台改变而重做颜色、圆角、像素边框或页面构图。

### 3.3 操作系统外壳不属于产品 UI

参考图中的 Windows 壁纸、桌面图标、任务栏、搜索框、系统托盘、日期和窗口控制按钮只是展示环境，不作为 renderer 产品 UI 资产实现。

需要保留的是窗口内部、桌宠、气泡、菜单和排排坐等产品自有表面。Windows 系统托盘、透明窗口、任务栏 `workArea`、虚拟桌面、混合 DPI 和活动能力状态由 Electron main、preload 与平台适配层承担，renderer 不模拟系统能力。

### 5.2 字体

```css

  "PingFang SC",
  "Microsoft YaHei",
  "Noto Sans CJK SC",
  system-ui,
  sans-serif;
```

| 级别 | 字号/行高 | 字重 | 用途 |
|---|---|---|---|
| `display` | `40/48` | 700 | 登录标题、胜利结果 |
| `title-1` | `28/36` | 700 | 页面主标题 |

| `caption` | `12/18` | 400 | 时间、状态和备注 |

### 5.3 间距与尺寸

- 基础间距单位：`4px`；
- 常用间距：`8 / 12 / 16 / 20 / 24 / 32 / 40px`；
- 表单控件高度：小型 `32px`、标准 `44px`、主要操作 `48px`；
- 图标标准尺寸：`16 / 20 / 24 / 32px`；
- 普通描边：`1px`；重点描边：`2px`；外层像素边框视觉厚度：`2–3px`；
- 内容区最小点击目标：`40×40px`；
- 页面主内容默认左右内边距：`32–40px`；
- 卡片内部默认间距：`16–24px`。

### 5.4 像素切角与阴影

- 所有主窗口、弹窗、气泡和菜单必须通过同一个 `PixelSurface` 组件生成外轮廓；
- 切角步长、描边厚度和阴影不得在页面样式中重复手写；
- 建议切角视觉步长为 `8px`，小气泡可使用 `6px`；
- 主窗口阴影保持短距离、低模糊、深棕灰，不使用大面积现代柔光；
- 气泡箭头属于 `PixelBubble` 组件，不通过文本符号、Emoji 或临时三角形占位。

## 7. 图标与美术资产规则

### 7.1 禁止的替代方式

- 不用 Emoji、Unicode 符号或文本字符假装图标；
- 不用 CSS 拼图、`div` 绘画、手写 SVG 或内联 SVG 伪造角色、商品和插画；
- 不把整张参考图当页面背景来冒充实现；
- 不拉伸、模糊或错误裁剪 Sprite Sheet。

### 7.2 现有可用资产

- `design/pet-action-prototypes/capybara/coin-hit-v1/`：水豚动作原型和静态帧；
- `design/pet-action-prototypes/effects/coin-drop-v2/`：登录金币前景特效；
- `design/pet-action-prototypes/qa/pet-action-pack-v1/`：3 个角色、9 套基础动作与 2 套共享金币特效的原型资产索引和 QA 记录；
- 参考图中的已确认角色、帽子和商品构图。

### 7.3 尚缺与待授权资产

水豚、鹈鹕、暹罗猫的 `WORK_NORMAL / SLACKING / TYPE_FRENZY`，以及共享 `COIN_OUT / COIN_IN_GLOW` 已完成原型交付和自动 QA，但仍需 Magnus 最终视觉确认、AI 模型与来源许可复核，并在客户端接入后取得真实 Windows 混合 DPI 渲染证据。好友角色、完整帽子缩略图、商店商品、机器人、钱包和日历等像素图标目前多数只存在于合成参考图中。实现前按以下顺序处理：

1. 查找仓库中的原始独立资产；
2. 若只有合成图，评估是否可无损提取；
3. 无法无损提取时，使用 ImageGen 制作同风格独立位图并由 Magnus 评审；
4. 标准 UI 图标使用最接近参考图的成熟图标库；
5. 缺失资产不得用占位方块交付视觉 QA。

资产必须登记来源、用途、尺寸和许可状态。未经确认的 AI 生成资产只能标记为 UI 原型资产，不得宣称可商用发布。

## 8. 页面布局规则

### 8.1 QA 舞台

- 历史参考图舞台约为 `1487×1058px`；
- 视觉对比只比较产品自有 UI 的裁剪区域；
- 00、02、18 等桌面叠加场景分别比较桌宠、角色行、气泡和菜单，不比较 Windows 壁纸与任务栏；
- 每个正式界面提供稳定的 `screenId` 和 `state`，确保能够重复打开相同内容。

### 8.2 响应与缩放

- 第一目标是参考图逻辑尺寸下的精确还原；
- 窗口不足时优先缩小内容留白或提供内部滚动，不擅自改成移动端布局；
- 主窗口需要定义最小宽高，低于最小值时不压扁文字或图片；
- 角色和像素资源只按整数倍或渲染器允许的最近邻比例缩放；
- renderer 窗口布局不得硬编码 Windows 任务栏位置；透明桌宠定位由 main 读取真实 `workArea`。

### 8.3 页面族

| 页面族 | 正式界面 | 共享重点 |
|---|---|---|
| 桌面叠加 | 00、01、02、18 | 透明背景、桌宠锚点、气泡、菜单和角色行 |
| 账号与设置 | 03、04、15、16、17 | 双栏表单、设置侧栏、开关、权限和账号卡片 |
| 任务闭环 | 05、06、07、12、13 | 任务行、AI 建议、时间轴、进度和结果弹窗 |
| 社交 | 02、08、18 | 好友状态、单向隐藏和两个独立可见性设置 |
| 经济装扮 | 09、10、11 | 钱包、商品卡片、库存、角色和帽子塔 |
| 活动只读 | 14、15 | 当前识别、历史时间线、权限状态；无纠正入口 |

## 9. Mock 数据与功能接入边界

### 9.1 Mock 原则

- 页面使用稳定、可复现的固定数据，不依赖随机值和当前网络；
- 任务、好友、商品、钱包和识别状态使用与共享契约一致的枚举语义；
- 金额示例使用整数人民币分转换，不在 UI 中实现正式经济计算；
- 时间轴和日程示例可以固定在参考图日期，视觉 QA 不跟随系统日期变化；
- 不把尚未确认的 PRD 建议值写成永久产品常量。

### 9.2 交互要求

以下主流程必须使用 Mock 状态真实可操作：

1. 登录/注册标签切换、用户名密码表单和密码可见性；
2. 工作设置字段修改与右侧预览更新；
3. 新建任务后进入 AI 建议确认；
4. 采用、修改、拒绝建议并点击“确认建议”；
5. 日程块选择、锁定、模拟拖动和确认；
6. 好友申请接受/拒绝、选择好友和“不对其展示”；
7. 钱包进入商店、选择商品和购买确认预览；
8. 角色/帽子标签切换、帽子排序和保存装扮；
9. 跑路确认与成功结果切换；
10. 活动识别只读状态、权限开关和通知开关；
11. 账号资料、修改密码、退出和删除账号确认；
12. 快捷菜单、通知静音子菜单和两个独立可见性复选项。

真实 API、持久化和 Windows 系统操作由后续功能层注入。页面组件只接收数据和回调；renderer 不直接调用 Electron main、Node 或 Win32 API。

## 10. 工程边界

计划使用：

- Electron；
- React + TypeScript + Vite；
- CSS Custom Properties + CSS Modules；
- PixiJS 仅用于需要 Sprite、动作和帽子锚点的角色场景；
- 普通表单、列表、设置页和弹窗使用 React DOM；
- Zustand 仅保存跨页面演示状态，不承担服务端权威数据；
- Vitest + React Testing Library；
- Playwright Electron 在工程可用后覆盖关键演示路径。

目录边界：

```text
apps/desktop/
  main/                 Electron 窗口和 Windows 平台边界
  preload/              最小、类型化 IPC
  renderer/
    app/                页面入口、路由和 Mock 场景
    components/         通用 UI 组件
    features/           按页面族组织的 UI
    styles/             令牌和全局基础样式
```

UI 组件不得直接导入 `electron`、Node API 或原生模块。

## 12. 视觉 QA 门禁

每个界面交付前必须：

1. 打开权威参考图；
2. 在固定 `screenId + state` 下捕获实现图；
3. 使用相同产品 UI 裁剪范围并排比较；
4. 记录外框、网格、间距、字体、边框、颜色、资产、溢出和状态差异；
5. 修复 P0/P1/P2 差异；
6. 再次捕获和比较；
7. 通过后才能进入集成。

目标公差：

- 主表面边界与主要列宽：参考尺寸下误差不超过 `2px`；
- 主要组件间距：误差不超过 `2px`；
- 字号和行高：误差不超过 `1px`，允许操作系统字体抗锯齿差异；
- 主色和表面色：以统一令牌为准，不允许页面内出现肉眼可见色偏；
- 像素资产：不得模糊、变形、缺失或使用错误动作帧；
- 核心流程控件：必须可操作，不得只做静态外壳。

构建成功、HTTP 可访问或截图存在都不等于视觉 QA 通过。参考图与实现图必须在相同状态下共同检查。

## 13. Figma 使用决定

当前不建立 28 屏完整 Figma 重绘稿。原因：代码是后续功能接入的正式交付物，先把所有 PNG 重画进 Figma会增加一次人工失真和维护源。

仅在以下情况建立小型 Figma 参考文件：

- 首个校准页仍无法从 PNG 确认切角、网格或组件边界；
- Magnus 或同事需要可视化标注而无法直接使用代码 Story/截图；
- 需要集中评审令牌、按钮、表单、侧栏或卡片变体。

若创建 Figma，只包含 Foundations、Components 和必要 Redlines；参考图 + 本规范仍是视觉权威，运行时代码仍是功能接入载体。

## 14. 已知风险与未验证范围

1. 参考图由视觉生成流程产出，部分页面的同类控件存在 1–4px 和色彩差异；本规范要求统一组件优先，而不是复制每一处偶然差异。
2. 多数好友角色、帽子和商品缺少独立源文件，可能需要无损提取或重新生成；未完成资产评审前不能宣称最终美术还原。
3. 当前开发环境为 Windows，可验证 renderer、Mock 交互和截图还原；真实托盘、透明窗口、混合 DPI、输入钩子、截图降级和另一台 Windows 机器启动仍需逐项取得证据。
4. PRD 仍有经济、承诺冻结、隐私权限和帽子超高视口等待确认项；UI 可以展示非承诺性的 Mock 状态，但不得把建议值编码成正式规则。
5. 视觉还原测试不证明真实登录、AI、排程、经济、好友同步或桌面识别功能可用。

## 15. 完成定义

UI 全套还原只有同时满足以下条件才算完成：

- 19 个正式界面均有可重复打开的固定状态；
- 所有 v2 修订和新版 PRD 删除项已落实；
- 共享组件和令牌没有被页面私自复制；
- 核心演示交互可从头走通；
- 所有可见位图资产已放置，无临时占位方块；
- 类型检查、构建和相关组件测试通过；
- 每个正式界面完成同视口视觉对比并修复 P0/P1/P2；
- 明确记录真实 Windows 系统能力和真实业务功能的未验证范围；
- 后续开发者可以通过替换 Mock 数据与回调接入功能，无需重写 UI。
